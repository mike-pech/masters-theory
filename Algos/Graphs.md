> Граф — это множество вершин (узлов, нод) и рёбер, которые соединяют эти вершины. E — множество рёбер, V — множество узлов

 Граф может быть *соединённым*, если все его вершины соединены рёбрами (не обязательно циклично).
- Граф может быть *цикличным*, если из его вершины можно проложить путь к ней же самой.

- Граф может быть *конечным* или *бесконечным*.

- Граф является *простым*, если все его вершины имеют не больше одного ребра и не содержат петель. Если граф содержит петли, то он называется **псевдографом**

- Граф может быть *направленным*, если рёбра имеют направления. Иначе, он *ненаправленный*.

- Граф называется мультиграфом, если множество его рёбер содержит параллелльные рёбра. По аналогии с простым графом, если мультиграф содержит петли, то называется псевдомультиграфом. 

- Граф называется нуль-графом, если множество его рёбер пустое

- Полный граф — это простой связный граф, в котором каждая пара вершин смежна.

Граф G называется изоморфным графу H, если для него существует биекция f из множества вершин графа G в множество вершин графа H, которая при этом сохраняет инцидентность рёбер графа G в графе H и наоборот. В случае с направленными графами также должная сохраняться ориентация рёбер. В случае со взвешенными графами должен сохранятся вес. 

Подграф, т.е. подмножество вершин и рёбер графа является графом.

Теория графов не обладает устоявшейся терминологией. Поэтому в некоторых публикациях могут использоваться термины, отличные от приведенных ниже.

_Вершина (узел, точка)_ (vertex, node, point) графа G есть элемент множества вершин v∈V(G);
- _Ребро (линия)_ (edge, line) графа G есть элемент множества ребер e∈E(G) или e={v1,v2}, где v1∈V(G),v2∈V(G)

- _Элементами_ графа G называются его вершины v∈V(G) и рёбра e∈E(G)графа

- _Порядок_ (order) графа G есть кардинальное число множества вершин n=|V(G)| или, другими словами, количество вершин

- _Размер_ (size) графа G есть кардинальное число множества ребер m=|E(G)|или, другими словами, количество ребер

- Вершина v _инцидентна_ (incident) ребру e, если v∈e; тогда еще говорят, что e есть ребро при v

- _Концевые вершины (концы)_ (endvertices, ends) есть две вершины, инцидентные ребру. Ребро _соединяет_ (joins) свои концевые вершины

- _Соседние (смежные) вершины_ (neighbours, adjacent) есть такие вершины v1 и v2 что {v1,v2}∈E(G) или, другими, словами обе вершины являются концевыми для одного ребра

- _Смежные ребра_ ( adjacent edges) это ребра, инцидентные одной вершине или e1={v,v1} и e2={v,v2} — смежные

- _Степень (валентность) вершины_ (degree, valency) d⁡(v) есть количество инцидентных ей рёбер. В направленных графах разделяют также степень входа и степень выхода (self-explanatory)

- _Изолированной вершиной_ (isolated) называется вершина со степенью d(v)=0, то есть не является концом ни для одного ребра

- _Висячей вершиной (листом)_ (leaf) называется вершина со степенью d(v)=1, то есть которая является концом ровно одного ребра.

## Обходы
### Обход в глубину (Depth-first Search)

Три вида вершин
- Белый — ещё не обработали вершину
- Серый — уже были на этой вершине, но не закончили обработку (есть куда идти)
- Чёрный — вершина обработана (некуда уже идти)

Так мы запускаемся и ходим по смежным вершинам в глубину, на каждом шаге красим вершину в серый и идём на белые вершины. Если из белой вершины больше некуда идти, кроме серой, то мы закрашиваем серые вершины в чёрный — там мы уже были

Таким образом мы возвращаемся в белые вершины и проходим другие белые вершины, пока все вершины не станут чёрными 

Алгоритм реализовывается либо циклом, либо рекурсией

```
dfsInternal(v) {
	v.color = 1
	for (u: G(v)) {
		if (u.color == 0) {
			dfs(u)
		}
	}
	v.color = 2
	}

dfs() {
	for(v : V) {
		if (v.color == 0) {
			dfsInternal(v)    // Если нужен счётчик глубины,
		}                     // то добавляем его в функцию — dfsInternal(v, count)
	}
}
```
### Обход в ширину — Breadth-first Search (BFS)

Понадобится очередь на обработку вершин и два класса вершин:
- Белый — не обрабатывали
- Чёрный — в очереди на обработку или уже обработали

1. Достаём вершину из очереди
2. Рассматриваем все смежные ей вершины
3. Добавляем смежные вершины в очередь, красим их в чёрный
4. Повторяем, пока очередь не опустет

```
bfs(init_v, q) {
	q.enqueue(init_v)
	// dist[init_v] = 0 для поиска кратчайшего пути
	while (!q.empty()) {
		v = q.dequeue
		for (u: G[v]) {
			if (color[u] == 0) {
				q.enqueue(u)
				color[u] = 1
				// dist[u] = dist[v] + weight(u) или вес текущей вершины
			}
		}
	}
	bfs(q.next(), q)
}
```

BFS может помочь с поиском кратчайшего пути в графе от одной вершины к другой. Это достигается введением дополнительного счётчика для каждой вершины, добавляемой в очередь по формуле $вес\_вершин\_до\_текущей$ + $вес\_текущей$

![[Pasted image 20251204190504.png]]

```
bfs(init_v, q) {
	q.enqueeue(init_v)
	dist[init_v] = 0 // массив расстояний
	while (!q.empty()) {
		v = q.dequeue
		for (u: G[v]) {
			if (color[u] == 0) {
				q.enqueue(u)
				color[u] = 1
				dist[u] = dist[v] + weight(u)  // +вес текущей вершины
			}
		}
	}
	bfs(q.next(), q)
}
```

В случае обработки взвешанного графа нужно сделать топологическую сортировку — расположить все рёбра графа слева-направо — это поможет рассматривать все пути в рассматриваемую вершину на итерации — как только мы нашли кратчайшее расстояние среди возможных, оно таким и остаётся

> [!INFO] Топологическая сортировка невозможна на цикличном и/или ненаправленном графе

Далее проходим по связям от начального ребра и проверяем пути, обновляя стоимости путей в массиве стоимостей (изначально с максимальными длинами) — производим _релаксацию_ (да, это так и называется видимо)

Затем получаем массив кратчайших путей — родителей — расстояний от конечной точки до v-той вершины, по которому мы можем восстановить путь хождением по кратчайшим расстояниям до самой первой точки

Время: O((V+E) × V)
Память: O(V)

### Кратчайший путь — Флойд-Уоршалл

Найти (кратчайшие) расстояния от всех вершин до всех вершин графа

Создаём матрицу V×V — матрицу смежности. Проверяем для каждой k вершины все пары вершин i и j и релаксируем

**Инвариант**: На каждой итерации в нашей матрице будут кратчайшие пути, которые проходят по вершинам, по номеру не больше, чем k (текущая итерация)
##### Асимптотика

**Время**: O(V³) (+ O(V) восстановлвение)
**Память**: O(V²)

> [!INFO] Отрицательные пути
> Если после V-1 итераций что-то поменялось в меньшую сторону — значит нашёлся отрицательный цикл
> Проходим V раз по родителям и дойдём до отрицательного цикла. Нашли вершину в отрицательном цикле — теперь мы можем найти все достижимые от неё вершины, которые лежат в отрицательном цикле
### Реализация

```c++
vector<int> weights(n, INT_MAX / 2);
weights[src] = 0;

for (int i = 0; i <= k; i++) {
    vector<int> temp = weights;
    for (auto& g : graph) {    // Граф как матрица смежности
        int u = g[0], v = g[1], w = g[2];
        if (weights[u] != INT_MAX/2 && w + weights[u] < temp[v])
	        temp[v] = w + weights[u];
	}
	weights = temp;
}

return (weights[dst] == INT_MAX/2) ? -1 : weights[dst];
```

#### Отрицательный цикл

```c++
void solve() {
    vector<int> d(n, INF);
    d[v] = 0;
    vector<int> p(n, -1);
    int x;
    for (int i = 0; i < n; ++i) {
        x = -1;    // Вершины с отрицательным циклом пока нет
        for (Edge e : edges)
            if (d[e.a] < INF)
                if (d[e.b] > d[e.a] + e.cost) {
                    d[e.b] = max(-INF, d[e.a] + e.cost); // Чтобы не overflow
                    p[e.b] = e.a;    // второе может быть ещё меньше))
                    x = e.b;    // Записываем вершину, которая поменялась
                                // на последней n итерации — это цикл!
                }
    }
    if (x == -1)    // Отрицательный цикл не появился
        cout << "No negative cycle from " << v;
    else {
        int y = x;
        for (int i = 0; i < n; ++i)
            y = p[y]; // Идём по циклу n раз, чтобы точно войти в цикл
        vector<int> path;
        for (int cur = y;; cur = p[cur]) {
            path.push_back(cur); // Собираем отрицательный цикл
            if (cur == y && path.size() > 1)
                break;
        }
        reverse(path.begin(), path.end());
        cout << "Negative cycle: ";
        for (int u : path)
            cout << u << ' ';
    }
}
```
## Восстановление путей

Относится ко всем алгоритмам кратчайших путей в графе. Для восстановления введём ещё один массив $P\ [0…n-1]$ с предпоследними (родительскими) вершинами на кратчайшем пути к той или иной вершине основного массива расстояний. Вообще, кратчайший путь к некоторой вершине $v$ лежит через кратчайший путь к вершине $P[a]$, и так далее 

```c++
typedef struct Edge {
	int a, b, cost;
} Edge;

void solve() {
    vector<int> d(n, INF);    // INF — верхняя граница
    d[v] = 0;
    vector<int> p(n, -1);

    for (;;) {    // Простой Беллман-Форд 
        bool any = false;    // Условие выхода
        for (Edge e : edges)
            if (d[e.a] < INF)
                if (d[e.b] > d[e.a] + e.cost) {
                    d[e.b] = d[e.a] + e.cost;
                    p[e.b] = e.a;    // Добавляем родительскую вершину
                    any = true;
                }
        if (!any)    // Ничего не поменялось — выходим
            break;
    }

    if (d[t] == INF)    // Нет пути в t — так и не прорелаксировали
        cout << "No path from " << v << " to " << t << ".";
    else {
        vector<int> path;
        for (int cur = t; cur != -1; cur = p[cur])
            path.push_back(cur);    // Идём назад от t до v и записываем путь
        reverse(path.begin(), path.end());    // Разворачиваем
		
        cout << "Path from " << v << " to " << t << ": ";
        for (int u : path)
            cout << u << ' ';
    }
}
```
# Минимальное остовное дерево
## Определение

Минимальное остовное дерево (minimal spanning tree) — Дерево (ацикличный граф),связывающий все вершины и имеющий минимально возможный вес рёбер
### Лемма о безопасном ребре (key lemma)

Пусть дан граф G с весовой функцией w. Если (S, V/S) — разрез графа G, а её ребро минимального веса, пересекающее этот разрез, то оно входит в какое-то MST графа G

Пример MST
## Алгоритмы
### Алгоритм Прима

Сборка MST через добавление к начальной вершине (и далее к другим вершинам) минимальное ребро до тех пор, пока не охватим все вершины графа, сделав MST

![[Pasted image 20251211194409.png]]
В этом разрезе смотрим из достижимых рёбер одно с минимальным весом — ребро 3–6 с весом 2
> [!INFO] Как найти минимальные рёбра?
> Аналогичный Дейкстре алгоритм, в котором мы рассматриваем ребро с максимальным приоритетом (минимальным ребром из MST до неё). Рассматриваем рёбра, исходящие из неё. И если какою-то ребро можно привязать дешевле, через эту вершину, то обновляем приоритет

![[Pasted image 20251211195142.png]]
Ребро 2 можно было привязать изначально за 8, а потом выяснилось, что можно привязать за 1 — соответственно обновляем приоритет, а затем и выбираем её как наименьшее ребро
### Алгоритм Крускала

Отсортируем рёбра в порядке возрастания весов. Далее идём от большего к меньшему и берём те, которые не образуют цикл — то есть соединяют разные компоненты (группы соединённых вершин)
