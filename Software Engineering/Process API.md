Стандартный API UNIX-систем для работы с процессами состоит из нескольких вызовов
## Основные вызовы
### `fork()`

Создаёт копию текущего процесса (с другой памятью и PID) 
### `wait()`

Ждёт выполнения дочернего процесса 
### `exec()`

Загружет бианрь и его аргументы (вместе с бинарем как аргумент 0) на место прежних аргументов (ранее сколнированных у родительского процесса) и даёт ОС выполнить прогу. Успешный вызов `exec()` никогда не возвращается

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

int main(int argc, char *argv[]) {
	printf("hello (pid:%d)\n", (int) getpid());
	int rc = fork(); // момент создания дочернего процесса
	if (rc < 0) {	// проваленный fork() имеет код -1
		fprintf(stderr, "fork failed\n");
		exit(1);
	} else if (rc == 0) { // у д
		printf("child (pid:%d)\n", (int) getpid());
		char *myargs[3];	// аргументы
		myargs[0] = strdup("wc");
		myargs[1] = strdup("proc.c");
		myargs[2] = NULL;
		execvp(myargs[0], myargs);
		printf("this shouldn't  print out"); // успешный вызов exec() никогда не возвращается
	} else {
		int rc_wait = wait(NULL); // родитель ждёт выхода дочернего процесса
		printf("parent of %d (wait:%d) (pid:%d)\n", rc, rc_wait, (int) getpid());
	}
	return 0;
}

```
## Почему?

UNIX-оболочка очень гибко использует эти три вызова для выполнения команд:

1. Юзак пишет в промпт команду и её аргументы
2. Оболочка сохраняет их себе в память
3. Оболочка зовёт `fork()`, "клонируя себя"
4. Оболочка зовёт в дочернем процессе `exec()` с ранее сохранёнными аргументами, меняя среду её исполнения на среду исполнения команды
5. Родительский процесс оболочки зовёт `wait()` и ждёт выполнения дочернего процесса
6. После выполнения процесса возвращается результат и/или код ошибки
7. Возвращается промпт

Также, при использовании перенаправления (`wc prog.c > word_count`), шелл закрывает свой стандартный вывод (регистр 1 в bash) и открывает файл `word_count`, чтобы записать результат команды туда

Также, при использовании трубы (`wc prog.c | less`), оболочка зовёт вызов `pipe()`, система создаёт буфер, который потом подключается к выводу первой команды и вводу второй команды
## Другие вызовы
### `kill()`

Посылает сигнал программе — остановиться (`SIGSTP`), умереть (`SIGINT`) и т.д. Некоторые сигналы интерпретируются самой программой, некоторые обязательны и гарантированно убивают процесс
